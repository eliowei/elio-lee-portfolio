Vue 3 のプロジェクトをアクセシビリティ基準に沿って改修していたとき、コンポーネントライブラリでは解決できない問題にぶつかりました。Vuetify の日付ピッカーは、キーボードだけでは操作を完結できず、スクリーンリーダーの読み上げも不完全だったのです。

日付のフィールドは複数のフォームに出てくるので、対処方法を共通の mixin にまとめ、ページごとに書かなくて済むようにしました。

## まず、ユーザーができる必要のある操作を洗い出す

問題を一つずつ直すのではなく、まずキーボードだけを使う人がどうやって日付を選ぶかを洗い出しました：

| キー | 期待される動作 |
|---|---|
| 矢印キー | 左右で 1 日、上下で 1 週間移動 |
| Enter | 日付を確定し、入力欄に戻る |
| Escape | ピッカーを閉じ、入力欄に戻る |
| 月や年を切り替えるとき | フォーカスが一覧の該当項目に移り、選び終えたら日付に戻る |

この表はそのまま受け入れ基準にもなりました。

## 矢印キー：動かすのは日付であって DOM ではない

日付の隣接関係を、隣のボタンを探して判断するべきではありません。月をまたぐと隣のボタンが存在しないことがあるからです。キーを日数に換算し、月や年のまたぎは `Date` に任せれば、ロジックはずっと単純になります：

```js
const OFFSETS = { ArrowLeft: -1, ArrowRight: 1, ArrowUp: -7, ArrowDown: 7 }

function moveDate(current, key) {
  const next = new Date(current)
  next.setDate(current.getDate() + OFFSETS[key])
  return next
}
```

選択可能な範囲を超える日付には移動せず、それ以外は呼び出し側が画面を更新してフォーカスを移します。

## フォーカス管理：画面が変わったら、フォーカスもついていく

ここがいちばん時間のかかった部分です。月を選ぶと月の一覧が日付のグリッドに置き換わり、フォーカスのあったボタンが消えて、フォーカスがページの先頭に戻ってしまいます。キーボードのユーザーにとっては迷子になったのと同じです。

そこで画面が切り替わるたびに、フォーカスの行き先を明確に決めるようにしました：

- 月や年の一覧を開く：現在の日付がある項目にフォーカスする。
- 月や年を選び終えたら：日付のグリッドに戻り、同じ日付、選択済みの日付、今日の順に探し、最後に最初の選択可能な日付にする。
- Enter や Escape で閉じる：元の入力欄に戻る。

月と年の一覧の矢印キーも別に処理する必要があります。複数列に並んでいるので、上下キーは 1 マスではなく 1 行分の数だけ移動しなければならないからです。

## 読み上げラベル：MutationObserver で補う

日付のボタンには、スクリーンリーダーが「2026年11月2日 月曜日」のように読み上げられる完全な名前が必要です。しかしこれらのボタンは Vuetify が生成していて、月を切り替えるたびに再描画されるので、開いたときに一度設定するだけでは足りません。

私の方法は、ピッカーの変化を監視し、まだラベルのないボタンにだけ `aria-label` を付けることです：

```js
const WEEK = ['日', '一', '二', '三', '四', '五', '六']

function labelDays(picker) {
  picker.querySelectorAll('.v-date-picker-month__day button').forEach((btn) => {
    const iso = btn.closest('.v-date-picker-month__day')?.dataset.vDate
    if (!iso || btn.hasAttribute('aria-label')) return
    const d = new Date(iso)
    btn.setAttribute('aria-label', `${d.getFullYear()}年${d.getMonth() + 1}月${d.getDate()}日 星期${WEEK[d.getDay()]}`)
  })
}

const observer = new MutationObserver(() => labelDays(picker))
observer.observe(picker, { childList: true, subtree: true })
```

（サイトが中国語なので、ラベルも中国語で生成しています。）ピッカーを閉じるときは忘れずに `disconnect()` してください。そうしないとオブザーバーがメモリに残ります。「ラベルのないボタンにだけ付ける」という判定も無駄ではありません。このコールバック自体も DOM を変更するので、毎回書き直すと不要な処理の繰り返しを招きやすいのです。

## コードを見るだけでなく、NVDA で検証する

`aria-label` を書いたからといって、正しく読み上げられるとは限りません。修正後は実際に NVDA を起動し、キーボードだけでフロー全体を通しました。ピッカーを開く、日付を移動する、月と年を切り替える、確定する、閉じる。各ステップでフォーカスの位置と読み上げ内容が期待どおりかを確認しました。

## 今回学んだこと

- コンポーネントライブラリはアクセシビリティを保証しない。多くの手間は省けるが、実際にフローを通すまでは、すべて対応済みだと思い込んではいけない。
- アクセシビリティは属性を足すことだけではない。キーボード操作の体験の核心はフォーカス管理にある。
- この方法は Vuetify のクラス名と DOM 構造に依存しているので、バージョンアップで動かなくなる可能性がある。アップグレードのたびに検証し直す必要がある。
