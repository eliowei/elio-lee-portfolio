よくある質問（FAQ）の Dialog で、ボタンで閉じる分にはまったく問題ないのに、キーボードの ESC で閉じたあとにもう一度開くボタンを押すと、ウィンドウが開かなくなりました。

## 原因：開閉の状態を 2 か所で持っていた

この Dialog の開閉は Vuex で管理していて、外部から action で開いていました：

```js
store.dispatch('toggleFAQdialog', { action: true })
```

ボタンで閉じると `closeFAQ` を通って状態が `false` に戻ります。問題は、ESC がこの経路を通らないことです。Vuetify の Dialog には ESC で閉じる機能が組み込まれていて、ウィンドウ自体は閉じますが、こちらの閉じる処理は実行されません。

その結果、状態はこうなっていました：

| タイミング | Vuex の状態 | 画面 |
|---|---|---|
| 開く | `true` | 表示 |
| ESC を押す | `true` のまま | 閉じる |
| もう一度開く | `true` → `true` | 変化なし |

状態が変わらないので Vue は更新をトリガーせず、当然画面も反応しません。

## 修正：ESC も同じ閉じる処理を通す

Dialog で ESC を監視し、同じ閉じるメソッドを呼びます：

```html
<v-dialog v-model="FAQdialog" @keydown.esc="closeFAQ">
```

これでどこから閉じても最終的に状態が `false` に戻り、両者が一致します。

## 同じ問題が起きるほかのケース

コンポーネントが独自の閉じ方を持っている場合は、状態が同期しているかを必ず確認します：

- ESC を押す
- オーバーレイをクリックする
- ルートを切り替える

これは `v-model` が重要な理由でもあります。双方向バインディングの setter が値を状態の出どころに実際に書き戻してはじめて、コンポーネント内部で閉じたことが外部にも反映されます。getter しかない computed をバインドしていたり、一方向の `:value` を使っていたりすると、この問題に簡単にぶつかります。

```js
computed: {
  dialog: {
    get() {
      return this.$store.state.showDialog
    },
    set(value) {
      this.$store.commit('setShowDialog', value)
    },
  },
}
```

## 今回学んだこと

- 同じ状態が 2 か所にあると、いずれ同期がずれる。
- 閉じる機能をテストするときは、ボタンだけでなくキーボードやオーバーレイも試す。
- 「2 回目だけ失敗する」バグは、たいてい状態がリセットされていないことを意味する。
